# SolvedOR Refactor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make SolvedOR give correct answers and honest visuals, then clean up its structure, translations and packaging so it can be deployed and shown publicly.

**Architecture:** Keep the stack (Streamlit + pyparsing + OR-Tools). Pull all solving into a pure, Streamlit-free `solver/` API (`solve_text`), move rendering and plotting into `ui/`, keep one session-state model, and load translations once. Fix correctness first (tasks 2–4), then structure (5–8), then docs/CI (9–10). Packaging is first because every later task needs reproducible installs and CI that runs on PRs.

**Tech Stack:** Python ≥ 3.11, uv, Streamlit, pyparsing, OR-Tools (GLOP for LP, SCIP for MIP), Plotly, pydantic, pytest, ruff, GitHub Actions.

**Spec:** the two audits of `main` @ c4652d8 (2026-10-27): solver audit (C1–C4, I1–I8) and app audit (1–19). Finding IDs below refer to them.

## Global Constraints

- `main` is protected: all work on branch `refactor/correctness-and-structure` from `origin/main`, merged by PR. Local checkout is on the stale `feat/modern-refactoring`: work in a separate worktree, never touch it.
- Commits authored as Vitor, no Claude co-author trailer. PR body ends with the Claude Code line.
- Default variable bounds are `>= 0` unless the model says otherwise (decision D1 below).
- Every user-facing string comes from `translations/{en,pt}.yaml`; EN and PT keys stay identical.
- `solver/` must not import `streamlit`.
- The 5 gallery examples in `resources/examples.yaml` must parse, solve and render in both languages after every task.

## Decisions (Vitor confirms before execution)

- **D1 Default bounds:** variables are `>= 0` unless declared otherwise in `where:` (textbook convention; matches what the app already prints). Free variables need an explicit `free x` or `x >= -inf`-style bound.
- **D2 Plot:** compute the real 2D feasible region from the constraints. Remove the hardcoded demo.
- **D3 CLI:** remove the broken `or-solver` console script and the unused `typer`, `rich`, `matplotlib` deps (the app has no CLI).
- **D4 Lockfile:** commit `uv.lock`; export `requirements.txt` from it for Streamlit Community Cloud (supersedes PR #7).
- **D5 Syntax scope:** add `≤ ≥`, signed and scientific numbers, optional colon after `subject to`/`s.t.`, general bounds `[num <=] var [<= num]`, `free`. Do **not** add decimal commas (they clash with `x, y >= 0` lists) or parentheses/division.

## Review Focus

1. Comma-separated variable lists in `where:` still parse after the number grammar changes (`x, y >= 0`, `integer a, b`). *(Task 2 test)*
2. A hard MIP pasted by a user returns within the time limit with a "time limit reached" status, never hangs. *(Task 4 test)*
3. Degenerate 2D regions (single point, segment, unbounded region, infeasible) render something sensible or no plot, never crash. *(Task 6 tests)*
4. Results survive a rerun: language switch and gallery clicks keep the last solution on screen. *(Task 7 AppTest)*
5. Old example texts and saved user models keep parsing (backward compatibility of the grammar). *(Task 2 test over `examples.yaml`)*
